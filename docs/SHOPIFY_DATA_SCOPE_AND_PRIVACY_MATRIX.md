# Shopify Data Scope And Privacy Matrix

## Purpose

This Task 229 matrix defines the proposed minimum Shopify data boundary for production-demand ingestion. It is architecture only. No scopes have been requested, no protected customer data has been imported and exact field availability remains subject to the stable GraphQL Admin API version selected in Task 233.

## Phase 1 Scope Decision

Proposed initial scopes:

- `read_orders` for source order/line and lifecycle evidence within Shopify's default order-history window;
- `read_products` for product/variant discovery and mapping evidence.

Phase 1 does not request write, customer, inventory, fulfilment, shipping or broad historical-order access by default. `read_all_orders` is separately approved by Shopify and is deferred unless an approved backfill requirement proves that more than the default 60-day window is necessary.

Order access and order webhooks are protected customer data even when direct customer fields are omitted. EveryBatch must therefore complete the applicable Shopify protected-customer-data review while still minimising direct fields.

## Role And Visibility Principles

- Shopify merchants can authorize their own store and see a limited connection surface. They do not receive target-manufacturer tenant access.
- Tenant integration managers can accept a relationship, configure mappings/facility/calendar and manage sync within their organisation after explicit relationship checks.
- Production users receive manufacturing demand and safe source references, not direct customer contact or address data.
- Support receives redacted shop/connection references, health categories, attempt IDs and blocker summaries only.
- Platform Admin receives environment, non-secret scopes, API version, health and lifecycle metadata, not credentials or unrestricted order payloads.
- Public and anonymous users receive no connection, source-order, credential or protected-data access.

## Decisions Requiring Confirmation

- Task 230 must prove whether postcode or state/region is necessary. Until then those fields are excluded.
- Task 233 must confirm every exact field, scope and webhook topic against its pinned stable API version and protected-data approval.
- Retention durations, anonymisation sufficiency, legal-hold exceptions, data processing agreements, privacy policy and subprocessor disclosure require qualified legal/privacy confirmation.
