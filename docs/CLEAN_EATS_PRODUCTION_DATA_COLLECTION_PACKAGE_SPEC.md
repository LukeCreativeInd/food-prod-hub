# Clean Eats Production Data Collection Package Specification

## Purpose And Audience

This is the canonical specification for the controlled workbook Luke can later issue to Clean Eats staff. It collects current approved production knowledge without making a spreadsheet canonical or copying legacy behavior. It is for operational owners, Product/Production reviewers, QA, material reviewers and the final approver.

No workbook is generated by Task 240 and this document contains no operational values.

## Package Structure

Use one versioned workbook plus referenced supporting evidence. The workbook contains protected instructions and controlled-value guidance, with one row per identity, Formula, input, Method, step, Work Instruction or evidence record.

| Tab | Purpose | Primary key/reference |
| --- | --- | --- |
| Instructions | Plain-language completion and submission rules | None |
| Item Register | Current Ingredients, Packaging, Components and Finished Products | `collection_item_key` |
| Formula Headers | Formula identity and nominal output basis | `collection_formula_key` |
| Formula Lines | Formula input composition | Formula key + `line_sequence` |
| Methods | Process identity, applicability and Formula compatibility | `collection_method_key` |
| Method Steps | Ordered process definition | Method key + `step_sequence` |
| Work Instructions | Reusable or step-specific operator guidance | `collection_instruction_key` |
| Area & Applicability | Existing/proposed area and facility mappings | `collection_area_key` |
| Yield & Batch Rules | Qualified process yield/loss and batch-envelope evidence | Stable rule key |
| Packaging Context | Product, assembly, dispatch and logistics classification | Stable context key |
| QA Links | Method-Step QA requirement references | Stable link key |
| Equipment & Resources | Applicability/capacity evidence | Stable resource key |
| Exceptions & Questions | Ambiguities and source conflicts | `collection_question_key` |
| Sign-off & Approval | Package and record-group attestations | Stable sign-off key |

## Staff Instructions

1. Enter what is done now, not what an old report says should happen.
2. Do not guess. Use an unresolved/question record when uncertain.
3. Use stable collection keys; do not enter database IDs or rely on row numbers.
4. Use one row per input and one row per process step.
5. Keep Formula quantities separate from Method steps and operator guidance.
6. State a UOM for every quantity and the basis for every percentage or ratio.
7. Reference a shared Component once; do not copy its raw ingredients into each parent Formula.
8. Classify water, processing aids and Packaging by physical/operational role.
9. Identify current source evidence and the responsible reviewer.
10. Complete sign-off only after blockers and conflicting evidence are resolved.

## Stable Keys

Keys use uppercase ASCII letters, numbers and hyphens and remain unchanged across a package revision: `ITEM-...`, `FORM-...`, `METHOD-...`, `WI-...`, `AREA-...`, `QUESTION-...`. They are staff-friendly transition references, not UUIDs. Duplicate or changed keys are blockers.

## Roles And Responsibilities

- **Product composition owner:** supplies and reviews Item/Formula truth; Clean Eats must nominate.
- **Production process owner:** supplies and reviews Method, Step, yield and batch truth; Clean Eats must nominate.
- **QA reviewer:** reviews QA linkages; Cettina or Luisa where nominated.
- **Warehouse/material reviewer:** reviews Packaging/material context where needed; Eddie where nominated.
- **Wholesale consultation:** Rob only where the record is wholesale-specific.
- **Final operational approver:** role must be nominated; Tony is known as Director/operational owner and approval sponsor, but per-record assignment is not presumed.

## Field Summary

The complete field contract is `PRODUCTION_DATA_COLLECTION_FIELD_DICTIONARY.md`. Required common evidence includes source type/name/version/reference, submitter/date, operational owner, reviewer/date, approval state/note, workflow state, evidence class and confidence.

## Sign-Off Process

Submitter attests that the record reflects current practice or clearly labels evidence otherwise. Domain reviewer validates meaning and dependencies. Final approver authorises `approved_for_import`. Formula, nominal output, Method, Work Instruction, yield/loss and batch constraints require explicit sign-off. QA-linked requirements require Production and QA review. Unresolved ambiguity cannot be signed off.

## Collection Order

Follow `CLEAN_EATS_PRODUCTION_DATA_COLLECTION_WAVES.md`: identity first; Components; Finished Products; Methods; Work Instructions and QA; yield/batch/facility/equipment; exceptions; final package sign-off. Drafting may overlap only where identifiers and dependencies are stable.

## File Naming And Versioning

Recommended filename: `clean-eats-production-collection-YYYYMMDD-vNN.xlsx`. Supporting evidence uses a safe descriptive filename and is registered in the package. A revision increments `vNN`; files are never overwritten in place after submission. A future system will calculate and retain checksums.

## Submission Rules

- Submit one complete package revision through the future approved private route; Task 240 creates no upload route.
- Include only necessary supporting evidence.
- Remove customer names, addresses, phone numbers and order-level PII.
- Do not email credentials, tokens or unrestricted exports with unrelated data.
- Record every omitted, unresolved or out-of-scope item in Exceptions & Questions.

## Corrections And Resubmissions

A correction creates a new workbook version and later a new source/import revision. The previous file remains immutable evidence. Identify which prior package is superseded and why. Never delete applied history or replace a reviewed file silently.

## Privacy And Commercial Sensitivity

Formulas, Methods, Work Instructions and QA-linked process requirements are proprietary tenant content. Access must be least privilege. Customer PII is out of scope unless explicitly justified. Support receives redacted diagnostics; Platform Admin receives redacted readiness only.

## Source Evidence

Accepted types include staff-entered current truth, controlled current document, current spreadsheet, supplier/manufacturer document, photo, verbal confirmation, existing EveryBatch record and legacy evidence. No source type is automatically approved. Record exact sheet/page/row and date/version where available.

## Structural Examples

- A Component such as **Bolognese Sauce** has an Item, Formula, nominal output, Method, steps, optional Work Instructions, yield evidence, area and QA links.
- A Finished Product such as **Naked Chicken** may reference Components, direct Ingredients and product-unit Packaging, with a separate assembly Method.
- A Component such as **Italian Herb Chicken Breast** separates composition from preparation/cooking Method and process yield.

No example supplies a Clean Eats quantity, instruction or approval.

## What Not To Do

Do not use a Recipe worksheet as canonical truth; copy legacy rows blindly; combine Formula output with process yield; treat planned/actual batch quantity as a Method rule; classify water or Packaging by cost alone; copy nested Component ingredients; invent missing area/equipment/QA references; enter UUIDs; average source conflicts; or assume workbook completion applies data.
